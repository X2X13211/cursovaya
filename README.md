### 1. Модель данных с валидацией (DataAnnotations)

В текущей версии проекта для проверки корректности вводимых данных используются встроенные аннотации из пространства имен `System.ComponentModel.DataAnnotations` (такие как `[Required]`, `[RegularExpression]`, `[EmailAddress]`). 
Проверка модели выполняется программно с помощью универсального метода `Validator.TryValidateObject`, что позволяет избавиться от избыточных ручных проверок и централизовать правила валидации прямо в классах сущностей (`User`, `User_Pasport`).

### 2. Код метода с обработкой исключений и пользовательским исключением

Самая рискованная операция в приложении — это этап взаимодействия с внешними ресурсами (базой данных SQLite) и первичный ввод пользовательских данных. 

Для обработки непредвиденных ситуаций и ошибок валидации в коде используются стандартные блоки `try-catch`, а также заложено пользовательское исключение `InvalidExceptionUser`, предназначенное для семантического разделения бизнес-ошибок от системных сбоев:

```csharp
public class InvalidExceptionUser : Exception 
{
    public InvalidExceptionUser(string message) : base(message) { }
}
```

### 3. Вызовы логирования с пояснением выбора уровня

Для отслеживания работы приложения реализован специализированный класс `AppLogger`, поддерживающий три уровня логирования (Information, Warning, Error):

1. **Уровень Information (Информационное сообщение)**
* **Пример использования:** `appLogger.Information("Email успешно прошел валидацию.");`
* **Пояснение:** Используется для подтверждения успешного выполнения штатных операций (успешное прохождение валидации полей, нахождение таблиц в базе данных).


2. **Уровень Warning (Предупреждение)**
* **Пример использования:** `appLogger.Warning(validationResult.ErrorMessage);`
* **Пояснение:** Фиксирует нарушения правил ввода данных пользователем. Приложение не завершает работу аварийно, а перехватывает ошибку и инициирует повторный ввод некорректного поля.


3. **Уровень Error (Критическая ошибка)**
* **Пример использования:** `appLogger.Error("Произошла ошибка при подключении к базе данных!", ex);`
* **Пояснение:** Применяется при возникновении исключительных ситуаций (например, сбой при открытии соединения с SQLite), с выводом детальной информации об ошибке.

### 4. Обоснование мер повышения надёжности

В архитектуре консольного приложения реализованы следующие механизмы обеспечения отказоустойчивости и безопасности:

* **Декларативная валидация:** Использование атрибутов `[Required]` и регулярных выражений (`RegularExpression`) предотвращает попадание некорректных данных в логику программы.
* **Изоляция и принцип Fail-Fast (Быстрый отказ):** Методы ввода данных обернуты в циклы с проверками, благодаря чему программа немедленно реагирует на неверный ввод (например, буквы вместо цифр или неверный формат даты) и запрашивает повторное значение до момента передачи данных в базу данных.
* **Безопасная работа с БД через параметризированные запросы:** Для предотвращения SQL-инъекций и повышения надежности все данные передаются в команды SQLite через параметры (`Parameters.AddWithValue`), исключая конкатенацию строк.
* **Управление ресурсами:** Использование конструкции `using` гарантирует корректное и своевременное закрытие подключений к базе данных и освобождение системных ресурсов.
