В рамках последнего обновления была заложена базовая архитектура для работы с данными, расширена структура пользовательского интерфейса и реализовано разделение ролей. Проект успешно переведен на использование базы данных.

## Реализованный функционал

### 1. База данных и архитектура
* Интегрирована и настроена реляционная система управления базами данных **SQLite**.
* Разработаны Entity-модели для взаимодействия с базой данных:
  * **Модель пользователя**: спроектирована для хранения персональных и академических данных заявителей.
  * **Модель администратора**: внедрена для управления приемом заявок от заявителей.
* Интегрирована базовая система логирования действий для отслеживания и фиксации изменений.

### 2. Серверная логика 
* Разработан контроллер пользователя для маршрутизации, валидации и обработки входящих данных с форм.
* Разработан контроллер администратора для управления процессом авторизации и доступа к закрытой части приложения.

### 3. Пользовательский интерфейс 
* Добавлена страница подтверждения об успешной подаче заявления на регистрацию.
* Добавлена страница подтверждения об успешной подаче заявления на ремонтные работы.
* Подготовлена демонстрационная модель представления и базовый макет страницы для панели администратора.

## План дальнейшей разработки 
В следующих обновлениях запланирована реализация следующего функционала:

1. Расширение и доработка существующей структуры базы данных, нормализация таблиц под будущие бизнес-требования.
2. Полноценная реализация сохранения данных новых пользователей из веб-форм напрямую в базу данных.
3. Настройка извлечения информации из базы данных и внедрение механизмов рендеринга списков пользователей и заявок на странице администратора.
4. Создание единой системы валидации, перехвата ошибок и их корректной визуальной отрисовки в пользовательском интерфейсе.
