# ОТЧЁТ ПО ПРАКТИЧЕСКОЙ РАБОТЕ № 3

**Название работы:** Приёмы надёжного программирования

**Тема курсовой работы:** Информационная система учета студентов для предоставления мест в общежитии

**Дата:** 10.09.2026 г.

---

### 1. Модель данных с валидацией

В текущем исходном коде валидация реализована вручную (через методы `Regex.IsMatch`, проверки `string.IsNullOrEmpty`, а также конструкции `try-catch`).

### 2. Код метода с обработкой исключений и списком пользовательских исключений

Самая рискованная операция в проекте — блок работы с базой данных, а также получение данных от пользователей, так как она требует высокой точности и строгой проверки.

### 3. Вызовы логирования с пояснением выбора уровня

В разработанном приложении уже реализован собственный класс `AppLogger` с методами `LogToUser` и `LogToDev`. Ниже приведено сопоставление этих методов со стандартными уровнями логирования и правилами передачи параметров:

**1. Уровень Information (Информационное сообщение)**

* **Пример использования:** `appLogger.LogToDev("Номер {PhoneNumber} успешно прошел валидацию.");`
* **Параметр:** `PhoneNumber` (`phone_number`).
* **Пояснение:** Используется для подтверждения успешного завершения этапов ввода данных. Необходим разработчику для отслеживания пути пользователя (User Journey).

**2. Уровень Warning (Предупреждение)**

* **Пример использования:** `appLogger.LogToDev("Валидация провалена: строка {DepartmentCode} не соответствует шаблону.");`
* **Параметр:** `DepartmentCode` (`code_pasport_number`).
* **Пояснение:** Фиксирует пользовательские ошибки (например, неверный формат ввода). Программа не падает (обрабатывается блоком `catch` с перезапуском метода ввода), но лог позволяет анализировать, какие поля вызывают у студентов наибольшие трудности.

### 4. Обоснование мер повышения надёжности

В текущей архитектуре проекта внедрены и планируются к расширению следующие меры надежности:

**Уже сделано:** проверка вводимых данных от пользователей, их корректность, логирование и обработка некоторых ошибок.

**Планируется:**

* Добавление различных уровней логирования;
* Расширение валидации и обработки ошибок внутри блока кода, связанного с БД;
* После проверки и по мере увеличения кодовой базы планируется рефакторинг некоторых частей кода для повышения удобства и читаемости;
* Дальнейшее ведение проекта будет построено с упором на безопасность данных, легкую поддержку и свободное тестирование.

**Отдельная мера — Принцип Fail-Fast (Быстрый отказ) через строгую изоляцию ввода:**

* **Обоснование:** В исходном коде методы ввода (`Enter_name`, `Enter_grounds_for_granting` и др.) изолированы индивидуальными блоками `try-catch`. При некорректном вводе (например, текст вместо цифр) приложение не доводит сломанные данные до базы данных, а мгновенно перехватывает `FormatException` и требует повторного ввода. Это компенсирует риск нарушения целостности базы данных на самом раннем этапе (санитизация данных).
