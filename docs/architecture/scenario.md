# Сценарный проход: проверка архитектуры

**Ключевой сценарий:** «Оформление заселения с автоматическим подбором свободного места и подписанием договора».

| № шага | Действие в сценарии | Пакет | Компонент | Узел | Риск / Что может пойти не так | Архитектурное решение для устранения риска |
|:---:|---|---|---|---|---|---|
| **1** | Студент подаёт заявку на заселение | `Presentation` | `Web UI Controller` | Клиент → Сервер приложений | Потеря запроса при сбое сети у студента | Идемпотентность API-запроса по уникальному токену `idempotency_key` |
| **2** | Комендант запускает автоподбор места | `Dormitory Inventory` | `Auto-Search Engine` | Сервер приложений | Алгоритм находит место, но параллельно другой комендант выбирает его же | Алгоритм возвращает список кандидатов, но окончательный захват происходит строго в транзакции |
| **3** | Подтверждение выбора и бронирование | `Tenancy Core` | `Tenancy & Check-In Core` | Сервер приложений → Сервер БД | **Гонка данных (Race Condition):** два коменданта одновременно фиксируют заселение на одно койко-место (овербукинг) | **Пессимистическая блокировка:** выполнение запроса `SELECT * FROM bed_places WHERE id = :id FOR UPDATE` в рамках открытой транзакции. Второй запрос ожидает снятия блокировки и получает статус «Место уже занято» |
| **4** | Формирование договора найма | `Tenancy Core` | `Tenancy & Check-In Core` | Сервер приложений | Сбой генератора PDF-файлов договора | Формирование метаданных договора в БД в единой транзакции с бронью; генерация бинарного PDF асинхронно |
| **5** | Студент подписывает договор в ЛК | `Presentation` → `Tenancy Core` | `Web UI Controller` → `Tenancy Core` | Сервер приложений | Истечение таймаута ожидания подписи студента | Резерв койко-места сохраняется 48 часов; при неподписании cron-джоба переводит место обратно в «Свободно» |
| **6** | Активация статуса жильца и начисление | `Tenancy Core` → `Billing` | `Tenancy Core` → `Billing & Debt Module` | Сервер приложений → Сервер БД | Заселение зарегистрировано, но счёт за первый месяц не создался | Вызов начисления выполняется через доменное событие `StudentCheckedInEvent` с гарантированной доставкой (Transactional Outbox) |
